# Architecture Guide

How the pieces of EnvForIO fit together. For the libraries, layout and request flow behind EnvForIO's features, see [envforio-design.md](./envforio-design.md).

## Where State Lives

| Kind of state                      | Where                                                  |
| ---------------------------------- | ------------------------------------------------------ |
| One component only                 | `useState`                                             |
| Shared UI state (sidebars, dialog) | Zustand stores in `src/store/`                         |
| App data and preferences           | TanStack Query hooks in `src/api/` and `src/services/` |

See [state-management.md](./state-management.md).

App data (tasks, projects, plans, ideas, papers, machines, calendars, feeds) is in SQLite (`envio.db`, via `rusqlite`), owned by Rust. The frontend reads and writes it only through Tauri commands. Preferences are a separate `preferences.json`. See [data-persistence.md](./data-persistence.md).

## Actions

User actions go through the [command system](./command-system.md) (`src/lib/commands/`), so the command palette, keyboard shortcuts and the native menu run the same code.

## File Organization

```
locales/                  # Translation JSON (en.json only)
src/
├── main.tsx             # Single entry point; picks the window from ?window=
├── windows/             # One folder per window (main, quick-pane, duo)
├── pages/               # Main-window pages (projects, plans, ideas, papers, ...)
├── api/                 # TanStack Query hooks over the Tauri commands
├── components/
│   ├── layout/          # MainWindow, sidebars
│   ├── command-palette/
│   ├── preferences/     # Preferences dialog and panes
│   ├── titlebar/        # Custom title bar and window controls
│   └── ui/              # shadcn/ui components
├── hooks/
├── i18n/
├── lib/
│   ├── bindings.ts      # Generated by tauri-specta (do not edit)
│   ├── tauri-bindings.ts # Re-exports the bindings; import commands from here
│   ├── commands/        # Command system
│   └── menu.ts          # Native menu builder
├── services/            # Preferences query hooks
└── store/               # Zustand stores
src-tauri/src/            # Rust backend, see rust-architecture.md
```

The main window is `src/components/layout/MainWindow.tsx`: title bar, left sidebar, `MainPane`, a right sidebar for task details, and the global `CommandPalette`, `PreferencesDialog` and `Toaster`.

## Windows

Every window loads `index.html?window=<name>`; `src/main.tsx` reads the parameter and lazily mounts the matching view from `src/windows/`. Windows run separate JavaScript contexts and share no React state.

| Window                    | Created in                             | View                     |
| ------------------------- | -------------------------------------- | ------------------------ |
| `main`                    | `tauri.conf.json`                      | `src/windows/main`       |
| `quick-pane`              | `src-tauri/src/commands/quick_pane.rs` | `src/windows/quick-pane` |
| `duo-capsule`, `duo-card` | `src-tauri/src/desktop/duo.rs`         | `src/windows/duo`        |
| `tray-menu`               | `src-tauri/src/desktop/tray_menu.rs`   | `src/windows/tray-menu`  |

The tray icon (`src-tauri/src/desktop/tray.rs`) keeps the app running when the main window is closed: closing `main` hides it, and Quit is in the tray menu. The menu is the `tray-menu` window (`tray_menu.rs`), drawn in the app's own style rather than as a native Win32 menu; Linux keeps a native menu because its tray sends no click events.

Windows talk through Tauri events:

| Event                                | Sent by                            | Effect                                  |
| ------------------------------------ | ---------------------------------- | --------------------------------------- |
| `tasks-changed`                      | `src/api/tasks.ts`, quick pane     | Other windows refetch tasks             |
| `theme-changed`                      | `src/components/ThemeProvider.tsx` | Quick pane re-reads the theme           |
| `open-calendar-day`                  | `src-tauri/src/desktop/duo.rs`     | Main window opens that day              |
| `calendars-changed`, `feeds-changed` | `src-tauri/src/desktop/refresh.rs` | `useInvalidateOn` refetches the queries |

## Security

- **Capabilities** are per window in `src-tauri/capabilities/`: `default.json` (main), `desktop.json` (main: window-state, autostart), `quick-pane.json`, `duo.json`, `tray-menu.json`. Give a window only the permissions it uses; never `["*"]`.
- **CSP** is in `src-tauri/tauri.conf.json`. All scripts are bundled; nothing loads from a CDN.
- **Input validation** happens in the Rust service layer, which returns `AppError::Invalid`. Shared checks are in `src-tauri/src/service/validate.rs`. User values go into SQL as bound parameters (`?1`), never through `format!`.
- **Atomic writes**: `preferences.json` and recovery files are written to a temp file and renamed (`src-tauri/src/commands/preferences.rs`, `recovery.rs`).
- EnvForIO stores no API tokens or passwords.

## Tauri Commands

Call Rust through the generated, typed bindings, never through string `invoke`:

```typescript
// ✅ GOOD
import { commands } from '@/lib/tauri-bindings'
const result = await commands.loadPreferences()

// ❌ BAD: no type safety
const prefs = await invoke<AppPreferences>('load_preferences')
```

See [tauri-commands.md](./tauri-commands.md).
